# 볼트 읽기 경로 다이어트 설계 — second-brain-template

날짜: 2026-09-25
상태: 초안 (사용자 스펙 리뷰 대기)

## 목표

볼트 기반 답변의 **정확도를 유지한 채 토큰을 줄인다.**

- 정확도: FESTA A/B 재측정에서 근거 충족률 ≥ 현행 B(15/16), 사실 오류 0
- 토큰: 현행 B 대비 입력 토큰 −40% 이상 (5회 반복 중앙값)
- 정확도가 한 점이라도 내려가면 채택하지 않는다 (§6)

## 배경 — 측정된 사실

출처: 2026-09-20 Codex A/B 파일럿 복원 로그, FESTA 실사용 세션(Claude 49 · Codex 35) 분석.

| 조건 | 입력 토큰 | 명령 | 근거 |
|---|---:|---:|---|
| 파일럿 B (볼트 노트만, 스킬·규칙·로그 없음) | 1.61M | 30 | 13/15 |
| 현행 B (볼트 + 스킬 + SECOND-BRAIN.md + log) | 3.43M | 67 | 15/16 |

현행 B의 토큰 누수 (입력 대비):
- 호출마다 재전송되는 기본 프롬프트 26–39% — 명령 수에 비례
- SECOND-BRAIN.md(24–30KB) + SKILL.md를 맨 먼저 읽어 이후 모든 호출에 동승 12–19%
- log.md 꼬리 80–120줄(줄당 ~775B) 8–12% — 답에 인용 0회
- 클러스터 통째 읽기 — 대부분 미인용

실사용에서 확인된 것:
- Codex 35세션 중 25개가 질문과 무관하게 세션 시작 때 규칙 전문 + 로그 꼬리(20–77KB)를 읽음
- Claude는 `@SECOND-BRAIN.md` import + 세션 훅으로 세션당 ~36KB 고정
- 30KB 초과 클러스터의 통째 읽기 12회가 **전부** Codex 출력 절단(앞뒤 ~20KB만 보임)에 걸림.
  `cluster-api-contract.md`(108KB)의 「활성 결정」 절(35.8–62.9KB 구간)은 통째로 잘림
- 클러스터가 색인이 아니라 변경 이력이 됨: 최대 108KB, 서술형 `## 갱신` 절 최대 24개,
  「현재 상태 요약」은 가장 오래된 부분
- 누락 1건(Q2)은 근거가 컨텍스트에 있었는데 답에서 빠진 **답 구성 실패**

참고한 외부 설계: lpaiu-cs/osk-system (MIT; 통치 문서는 저자 고유 저작물이므로 아이디어만
참고하고 문장은 옮기지 않는다). 가져온 원칙 — 허브는 멤버 목록이 아니라 갈래의 입구,
부분 읽기는 완전 검토가 아님, 상시 로드 텍스트는 예산을 둔다, 숫자 상한은 경고로만.
osk는 검색을 BM25 한 가지로 하고 status·topics를 쓰지 않으며 검색 품질을 측정하지 않았다 —
우리의 frontmatter·topics·status 필터 경로는 **그대로 유지**한다.

## 범위

바꾸는 것: `SECOND-BRAIN.md`, 신규 `second-brain/workflows/W1.md…W9.md`, `AGENTS.md`,
`.claude/hooks/session-context.mjs`, `.agents/hooks/session-context.mjs`,
`knowledge/_templates/cluster-index.md`, 신규 `knowledge/.ignore`, `bin/init.js`, `bin/test.sh`.

바꾸지 않는 것: 스킬 14개 × 2(이름·설명·본문), 노트 frontmatter 스키마, status 어휘,
W4 충돌 규칙, 기존 볼트 노트. 검색 스크립트는 재측정 후 별도 결정.

---

## 1. SECOND-BRAIN.md 분리 — 핵심 + 워크플로우 상세

스킬 본문("SECOND-BRAIN.md를 전부 읽고 W-n 실행")은 그대로 두고, 그 문서가 가리키는
내용만 줄인다.

```
SECOND-BRAIN.md                     (핵심, 목표 ≤ 10KB)
  Language / Vault layout / Frontmatter schema / Status 라이프사이클과 회수 시맨틱
  Topic slugs / 회수 규칙(§2) / Trigger routing / General rules
  워크플로우 색인 — "W-n을 실행할 때 second-brain/workflows/W<n>.md를 읽어라"
second-brain/workflows/W1.md … W9.md
  현재 SECOND-BRAIN.md의 W1–W9 본문을 문장 변경 없이 이동
```

- 이동은 **글자 그대로**다. `bin/test.sh`가 이동 전 원문과 이동 후 파일을 비교한다.
- 크기가 목표를 넘으면 스키마 절의 type별 상세를 줄이지 않고 그대로 둔다
  (정확도 우선 — 목표는 경고일 뿐).
- `second-brain/`은 설치기가 소유하는(마커 기반 갱신) 디렉터리로 추가한다(§5).

## 2. 회수 규칙 (SECOND-BRAIN.md 신규 절)

```
### 회수 규칙
1. 질문형(왜·무엇·현재 상태)은 답변 모드로 처리한다:
   주제 식별(_topics.md) → frontmatter의 topics·status로 근거 결정 후보를 좁힌다
   → 그 결정 노트 본문을 읽는다 → status·supersede 체인으로 현재성 확인
   → 같은 topic의 open 이슈 확인 → 하위 질문마다 답하고 id를 인용한다.
   W4·W6·W8 전체 경로는 구현 전 브리프(W3), 버그 질문(W6), 새 결정(W4)일 때만.
2. 클러스터는 통째로 읽지 않는다. 필요한 절(현재 상태 요약, 활성 결정 등)을
   제목으로 찾아 그 줄 범위만 읽는다.
3. 여러 파일을 한 명령으로 이어 붙여 읽지 않는다.
4. 출력이 잘렸으면 보지 못한 범위를 밝히고 "없음·충돌 없음"을 단정하지 않는다.
   부분 읽기는 전체 검토가 아니다.
5. 검색은 _sources/를 제외한다(knowledge/.ignore가 rg에 강제).
6. log.md는 회수 자료가 아니다. 특정 id·날짜·용어를 찾을 때만 검색한다.
7. 답하기 전에 근거 결정의 「결과」·「영향 범위」를 확인하고,
   질문의 하위 질문 중 빠진 것이 없는지 점검한다.
```

- `knowledge/.ignore`: `_sources/` 한 줄. ripgrep이 기본으로 따르는 파일이라 코드가 없다.
- 1번의 frontmatter 필터 단계는 현행 검색 규칙("frontmatter 먼저")과 동일하다 — 빠지는
  것은 질문형에서의 W4·W6·W8 **전체 수집**뿐이고, open 이슈 확인은 남긴다.

## 3. 세션 시작 로드 축소

| 대상 | 현재 | 변경 |
|---|---|---|
| `CLAUDE.md` | `@SECOND-BRAIN.md` | 그대로 (§1로 30KB → ≤10KB) |
| `AGENTS.md` | "세션 시작 때 SECOND-BRAIN.md 전부 읽기" + 로그 꼬리 읽기 | "볼트 작업일 때 SECOND-BRAIN.md(핵심)를 읽는다". 로그 꼬리 지시 삭제 |
| 세션 훅 2종 | `_topics.md` + log 15줄 (최대 ~26KB) | `_topics.md`만. 로그 꼬리 삭제 |
| `bin/init.js` `AGENTS_POINTER` | "SECOND-BRAIN.md를 전체 읽고…" | "볼트 작업 시 SECOND-BRAIN.md를 읽고…" |

세션 시작 컨텍스트 규칙(General rules)의 "log.md 꼬리를 읽어" 문구도 함께 고친다.

## 4. 클러스터를 계층 색인으로 (W2 + 템플릿)

W2 증분 갱신에 **방법**을 명시한다:
- 노트를 먼저 저장하고, 그다음 클러스터에 한 줄을 넣는다.
- 「현재 상태 요약」은 제자리에서 다시 쓰고 날짜를 갱신한다. 서술형 「갱신」 절을 만들지 않는다.
- 서술은 결정·이슈 노트 본문에 둔다.
- 한 갈래가 커지면 하위 클러스터 `cluster-<topic>--<sub>.md`로 나눈다. 부모는 하위
  클러스터를 한 줄로 가리키고, 그 멤버를 다시 나열하지 않는다. 멤버는 한 갈래에만 속한다.
- 하위 클러스터는 `topic`이 부모와 같고, `_topics.md`에 새 슬러그를 만들지 않는다.

W2 full 무결성 검사에 추가 (보고만, 자동 수정 없음):
- 12KB 초과 / 서술형 「갱신」 절 존재 / 요약 날짜가 최신 멤버의 `created`보다 오래됨
- 부모가 하위 클러스터의 멤버를 다시 나열함 / 부모에서 링크되지 않은 하위 클러스터

12KB는 **경고**다. 분할 여부는 주제가 실제로 갈라졌는지로 판단한다 — 숫자를 규칙으로
걸면 에이전트가 내용을 지워 맞추는 것이 osk에서 측정됐다. 세부를 옮기는 경로(노트 본문 /
하위 클러스터)를 규칙에 적어 삭제보다 이동이 쉬운 길이 되게 한다.

`cluster-index.md` 템플릿: 「현재 상태 요약」 안내에 "제자리 재작성, 서술형 갱신 절 금지"를,
목록 앞에 「하위 클러스터」 절(선택)을 추가한다.

기존 FESTA 클러스터 26개 정리는 이 스펙 밖이다 — 규칙 반영 후 FESTA에서 maintain으로
별도 승인받아 진행한다.

## 5. 설치기

- `buildPlan()`의 소유 디렉터리 목록에 `second-brain/workflows` 추가 (마커 기반 갱신).
- `knowledge/.ignore`는 `planIfMissing`.
- 기존 설치본의 `AGENTS.md` 포인터는 멱등 검사(`includes('SECOND-BRAIN.md')`)로 갱신되지
  않는다 — 설치 안내에 수동 수정 한 줄을 적는다.

## 6. 검증

자동 (`bin/test.sh`):
- 스킬 짝 byte-identical (기존)
- W1–W9 이동 전후 본문 동일 (분리 커밋 직전 원문을 기준 파일로 고정해 비교)
- 기존 grep 검사를 새 위치에 맞게 갱신 (W8·W9·무결성 검사 등은 workflows/에서 확인)
- SECOND-BRAIN.md 크기 보고, 훅 출력에 log 꼬리 없음, `knowledge/.ignore` 존재

측정 (FESTA, 채택 게이트):
- 조건: A / B(현행) / B'(개선). 셀당 5회, 조건 순서 교대
- 기록: 비캐시 입력·캐시 쓰기·캐시 읽기·출력, 명령 수, 절단된 출력 수, `_sources/` 접근
- 채점: 기존 루브릭 + 정답 노트 id 회수 여부. 한쪽 코퍼스에만 근거가 있는 항목은 따로 표시
- 질문: 기존 4개 + 큰 클러스터(api-contract, service-ui)를 치는 질문 2개
- **채택 조건: B' 근거 충족률 ≥ B, 오류 0, 입력 토큰 −40% 이상 (중앙값)**
- 미달 시 변경을 하나씩 되돌려 원인 격리: 답변 모드 → 절 단위 읽기 → 로그 제외 순
- 측정 세션에서는 전역 task-observer 등 템플릿 밖 훅을 끈다 (측정 오염 방지)

## 7. 결정하지 않은 것

- 검색 스크립트(`vault-search.mjs`, osk 토크나이저 이식 ~210줄): B' 측정에서 질문당 명령이
  8개를 넘으면 별도 스펙으로.
- 스킬 설명·이름 정리(report 충돌, 오작동 라우팅): 이번 범위 밖.
